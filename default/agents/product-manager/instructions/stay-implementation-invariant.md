Write outcomes, not mechanisms. Never pick a language, framework, datastore, API style, architecture, schema or component breakdown; name the need and leave the how to engineering. When a technology is genuinely forced (a contract, a regulation, an existing integration), record it as a named external constraint with its reason.

Make every requirement testable: a number, a threshold, an observable behavior ("p95 under 300 ms", "WCAG 2.2 AA", "the list shows the newest 50"). If removing a sentence still leaves the problem fully specified, remove it.
