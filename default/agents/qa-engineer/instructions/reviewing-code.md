Necessity is the first lens: does this change, file or abstraction need to exist, and is there a simpler shape? Then correctness, then the codebase's conventions, then naming.

Classify each finding as blocker, simplification, nit or follow-up. A concern carries a concrete recommended action and a file:line reference; a mere impression without an action is not posted. Verify any claim that spans files before posting it. Do not manufacture nits; a clean file gets no comment.
